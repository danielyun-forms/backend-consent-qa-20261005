What this run found

Ordinary local submissions reached the consumer and stored the expected tracking decisions. The material gap is failure handling: injected terminal and exhausted-retryable permission failures left an earlier ALLOW in place after a DENY request, without an automatic retry or the expected consumer error counter. Explicit manual replay after removing the fault stored DENY; that recovery does not resolve the original failure.

AC-05 records a narrower checklist mismatch: invalid input is rejected with HTTP 400, but one error message differs. Changed cases document expectations that no longer match the current implementation. Partial cases retain the exact boundary still unverified.

Protection behavior requiring review: In scoped local tests, a protection decision blocked marketing/list subscription, but both tracking ALLOW and DENY were still written afterward. The changed call order does not make this consequence a safety approval. See SE-01.

Environment caveat

The first message was delayed by a stopped local event publisher. Its fallback attempted S3 and failed with an expired credential; no successful remote write was observed. The local publisher was restored and S3 was explicitly pointed to the local emulator before subsequent checks. This setup failure is retained separately from the consent results. All reported subscription requests target the local app.
